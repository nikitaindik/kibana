# Parallel k6 Testing Script

This directory contains scripts that were used to run performance tests for "installation review" pagination implementation. Scripts use `k6` and `tmux` to run tests against multiple Kibana deployments in parallel.

## Prerequisites

Ensure you have the following installed:
- `k6`
- `tmux`

## Configuration

Before running the tests, you must configure your deployment targets in `run-k6-parallel.sh`:

1. Open `run-k6-parallel.sh`.
2. Locate the deployment functions (e.g., `deploy_main`, `deploy_branch_runtime`).
3. Fill in the `KIBANA_URL` and `PASSWORD` variables for each deployment you want to test.
4. Adjust input parameters (`TARGET_USERS`, `SMALL_PAGE_SIZE`, `LARGE_PAGE_SIZE`).
5. Adjust the `DEPLOYMENTS` array if you want to add or remove test targets.

## Usage

Run the script using the following commands:

```bash
tmux kill-session # If you already have a tmux session running, you can skip this step
./run-k6-parallel.sh
```

These commands will:
1. Kill any existing tmux sessions.
2. Start a new detached tmux session.
3. Split the window into panes for each configured deployment.
4. Run the k6 tests in parallel against all targets.

## Results

After the test runs complete, the results are processed automatically.
- Raw JSON results are saved to `results/results.<deployment_name>.json`.
- A human-readable summary is printed to the console and saved to `results/summary_<deployment_name>.txt`.

The summary includes:
- **Initial requests**: Total requests initiated.
- **Succeeded on first attempt**: Requests that succeeded immediately.
- **Needed retries**: Requests that failed initially and entered the retry loop.
    - **Resolved retries**: Requests that eventually succeeded after retries.
    - **Unresolved retries**: Requests that failed even after all retries.
- **Retry distribution**: A breakdown of how many retries were needed and the corresponding total wait time.
